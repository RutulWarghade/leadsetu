LeadSetu: an AI agent that turns messy buyer requirements into supplier matches

Rutul Narendra Warghade · MBA (1st Year), SVKM's Narsee Monjee Institute of Management Studies (NMIMS), Mumbai

Paste a buyer requirement in English, Hindi or Hinglish. The agent structures it, searches a supplier catalog with a retrieval tool, scores the lead, recommends suppliers and drafts a reply, then a guardrail checks it for invented suppliers.

Architecture

Understand

An LLM reads the raw requirement (English, Hindi or Hinglish) and extracts product, quantity, specs, city, timeline and budget into a fixed JSON structure. Unstated fields stay null rather than guessed.

Retrieve

The agent calls a search_suppliers tool itself. The tool runs BM25 ranking over 48 suppliers, expands Hinglish words (taar → wire, dabba → box) and boosts same-city and same-state suppliers.

Reason

The LLM judges fit honestly, marking a related-but-different product as medium fit, scores lead quality with a transparent rubric, and asks clarifying questions for price-critical gaps.

Verify

Code, not the LLM, checks every recommended supplier ID against both the catalog and the tool results from this run. Anything invented is removed and flagged.

Why this matters for a B2B marketplace

Buyer requirements arrive short, informal and often in Hinglish. Vague leads waste supplier time, and poorly matched leads lower response rates. Structuring each requirement, scoring its quality, and routing it to fitting nearby suppliers can improve both buyer satisfaction and supplier conversion.

Design trade-offs

  • Keyword (BM25) retrieval instead of embeddings: transparent, free and fast for a 48-row catalog. At marketplace scale, embeddings plus a vector database would capture meaning better (e.g. "pani saaf karne ki machine" → RO plant).
  • Fast vs balanced model: the fast tier replies in seconds at lower token cost; the balanced tier reasons better on ambiguous requests. The evaluation tab measures the difference.
  • Guardrail in code: LLMs can produce confident, wrong answers, so supplier IDs are verified deterministically instead of trusting the model.
  • Prompt injection defence: buyer text is wrapped in delimiters and treated as data, never as instructions.

Tools

LLM with tool calling (Claude), structured JSON output, few-shot prompting, BM25 retrieval in JavaScript, HTML/CSS. Supplier catalog is synthetic sample data created for this project; it is not real marketplace data.
